# Agent runtime (sessions, hand-over, catch-up, deferral) — mini-spec

**Status:** draft 3 for gate G7, 2026-10-27 (two review rounds; resolutions
§9 and §10). Module C4 (with C3 sandbox provider, C5 harness adapter). Design
source: `ALEMBIC-WORKSPACE-DESIGN.md` §5; FC-16 v1 draft Part A; write-path
and queue specs.

## 1. Pieces

| Piece | Where | What |
|---|---|---|
| **Session** | `agent_sessions(id, package_id unique, reasons text[], sandbox_ref, harness_version, created_at)` | one per course |
| **Event log** | `session_events(session_id, seq bigint generated by the server, kind enum, payload jsonb ≤ 64 KiB, at)` | 90-day retention |
| **Job** | `jobs(id, session_id, payer_account_id, invoker_id, kind, status, gateway_key_id, signing_kid)`; unique partial index `(session_id) where status = 'running'` (one running session job) | |
| **Changeset registry** | `agent_changesets(id pk = changesetId, package_id, job_id, invoker_id, status in ('pending','queued','done','bounced','refused','purged'), queue_row_id, depends_on)` | one record from first receipt, whether pending or queued (R-12) |
| **Sandbox** | SandboxProvider (C3) | **one per course**, never shared or reused (R-3) |
| **Harness** | C5 adapter | the official agent with the Coursewerk harness |

## 2. Authentication and secrets (R-1, R-2)

- **The session token is never visible to the agent.** Like the AI key, it
  lives in the sandbox's outbound layer:
  - testing: an instabox Secret scoped to Alembic's agent endpoint host;
  - production: the sidecar that holds the AI key.
  
  The agent's requests carry a placeholder; the real token is added on the
  way out.
- **The token** is a JWT signed with a **dedicated agent key** (never the
  Supabase JWT secret), with:
  - `typ = "alembic-agent"`, `aud = "alembic-agent-api"`;
  - `{package_id, session_id, job_id, invoker_id}`;
  - `exp ≤ 15 min`, renewed by the orchestrator.

  Every request is refused unless the job is the session's **current
  running** job, and the package matches session, job and changeset.
  Renewal re-checks the invoker's membership. A Supabase user JWT is never
  accepted on these endpoints, and an agent token never works against
  PostgREST: different key, different audience.
- **The fetch proxy refuses:**
  - Alembic's own hosts (including the agent API);
  - private, loopback, link-local and metadata addresses, and Fly
    `.internal` names, checked after DNS resolution and on every redirect;
  - query strings over 512 bytes;
  - any URL containing a known token prefix.

## 3. Sandboxes and isolation (R-3)

- **Production (Fly):** each course's sandbox is its own Machine in a
  dedicated Fly app for sandboxes, with no other services in that app or
  organisation's private network. Machine-level firewall rules drop all
  traffic except to the gateway and the fetch proxy, so private-network
  (6PN) traffic to peer machines is refused too. Volumes are created per
  course and destroyed with the sandbox, never reused.
- **Testing (instabox free plan):** one VM. Each course gets its own Linux
  user and home, with nftables rules per user: only the gateway, the fetch
  proxy and Alembic's agent endpoint are reachable (the latter through the
  Secret injection). Users can't read each other's homes (mode 700). This is
  weaker than one VM per course, and accepted for a handful of known
  testers (O22).
- Claim R.7 tests both: no egress beyond the allowed hosts, **and** no
  reachability of a peer sandbox, the worker, `.internal` or metadata
  addresses.

## 4. Endpoints (Vercel, service role behind token checks)

### 4.1 `POST /api/agent/changesets`

1. Verify the token (§2).
2. Register `changesetId` in `agent_changesets`. A repeat returns the
   existing record (R-12).
3. Check each path with `canWritePath('agent', path, {invoker})`. Harness
   records are allowed; their content is not trusted (§6).
4. Refuse when the course is read-only, the job is cancelled, or the
   session is `paused:owner` or `paused:handout` (A-2).
5. Decide:
   - any file being edited → `pending`;
   - `dependsOn` points at a changeset that is not yet queued → `pending`;
   - else `queue_insert(kind 'changeset', idem = changesetId, invoker =
     token.invoker_id, depends_on = <the dependency's queue row id>)` →
     `queued`.

   A `changeset` row carries `invoker_id` and no `actor_id`.

### 4.2 `GET /api/agent/changesets/:id`

Only for a changeset of the token's package and job (R-9).

### 4.3 `GET /api/agent/changes?since=<path→version>`

Returns, for paths of this course only:
- the working repo head's changed files, with actor and door;
- **this job's own** pending and queued changesets.

It never returns other members' unsynced drafts (`sync` rows) (R-8).

`private/instructor/` content is included: the agent may edit it
(`edit.private`). **Sources are never returned here.** An AI-allowed source
is fetched through `GET /api/agent/sources/:id`, which checks
`canAgent(invoker, 'source.use-ai', {aiAllowed})` against the `sources` row
and returns a signed link valid for 60 s.

### 4.4 `POST /api/agent/events` (R-4)

- `kind` is a closed enum: `message`, `tool`, `progress`, `question`,
  `handover-note`. Payloads ≤ 64 KiB. At most 120 events a minute per
  session. `seq` is assigned by the server.
- A `question` creates exactly one Needs-you item type, **"Question from
  the assistant"**:
  - its text is shown as untrusted plain text (no links, no HTML);
  - its only actions are a free-text or multiple-choice answer.
  
  The agent can't create any other item kind (Approve, Both changed,
  Reconnect GitHub, Publish…).
- **An answer is never an approval, a publish, or a permission grant.**
  Approvals and Tier-3 actions happen only through their own UI and
  endpoints.

## 5. Deferral and pending changes (R-7, A-1)

- **Periodic job:** every 30 s, the orchestrator re-offers pending
  changesets in creation order. One becomes `queued` when none of its files
  is being edited **and** its `dependsOn` (if any) is queued.
- **30-minute bound:** counted from when the changeset became eligible, so
  a dependent's clock starts only once its dependency is queued. The
  dependency always goes first. After the bound, the changeset is queued
  with `fromOpenEditor = false`. A cycle among pending changesets is
  impossible: `dependsOn` must name an already-registered changeset.
- **Removal or cancellation:** the invoker's pending changesets become
  `purged` at once, and their queued rows are refused at execution.
- **Per-path re-check at execution:** the committer re-checks every path
  with the invoker's **current** role (`permitted()` in the committer). A
  deputy whose term ended can't land deputy-only files.

## 6. Agent-authored content (R-5, R-11)

- **The agent may read private instructor files and AI-allowed sources.**
  What stops their text reaching students is Publish's answer-key and
  copying checks (B5): any 12-word run from `private/instructor/` blocks,
  and so do passages over 50 words matching a source's fingerprints.
- **The Publish summary lists every file the agent changed since the last
  Publish**, with a link to see the changes, so the approver sees what the
  agent wrote.
- **Records are claims, not authority.** `private/coursewerk/` records are
  written by the harness, and an injected agent could forge them. Alembic
  never derives a permission or an approval from them. They are public only
  through the publish profile, which writes JSON validated against a schema,
  with text fields length-limited and rendered as plain text.

## 7. Session reasons and endpoint behaviour (A-2, A-3)

`reasons ⊆ {working, waiting, paused:owner, paused:handout, paused:github,
paused:budget, unavailable}`.

| Reason | Hand-over | Events | Catch-up |
|---|---|---|---|
| paused:owner, paused:handout | refused | accepted | accepted |
| paused:github | accepted (queued; it waits) | accepted | accepted |
| paused:budget | accepted for the current step; the next step needs `extend` on the job's hold (ledger §9.9) | accepted | accepted |
| unavailable | — | — | — |

**Quick asks** use no sandbox. Vercel calls the gateway with a per-ask key
and a hold on the asker's account. The answer returns to the asker's editor
and goes through the sync path when accepted.

**Automatic jobs** (R-10) run with the rights of the person whose action
triggered them, capped at co-author rights: `canAgent(min(triggerer,
'co-author'))`. They are paid from the course allowance. Owner-only paths
are never written by automatic work.

## 8. Claims

| Claim | What |
|---|---|
| R.1 | a token signed with any other key, with another `aud`/`typ`, for another course, or for a job that isn't the session's current running job is refused; a Supabase user JWT is refused |
| R.2 | the agent can't write any path its invoker couldn't, end to end; automatic jobs never exceed co-author rights |
| R.3 | hand-over is idempotent across the pending and queued states |
| R.4 | a changeset touching an open file is deferred, stored in the database, re-offered after the editor goes idle, and queued after 30 min of eligibility at the latest |
| R.5 | dependsOn order holds across deferral; a dependent never goes first |
| R.6 | catch-up returns only this course, this job's own changesets, never others' drafts or source files |
| R.7 | a sandbox reaches only the gateway, the fetch proxy and (through the injected secret) the agent API: not peers, the worker, `.internal`, metadata or Alembic's other hosts |
| R.8 | removing the invoker purges their pending changesets and refuses their queued ones |
| R.9 | cross-course `GET changesets/:id` refused |
| R.10 | events: unknown kind refused, size and rate limited; the agent can create only "Question from the assistant" items; an answer never approves or publishes |
| R.11 | members can't write `agent_sessions`, `session_events`, `agent_changesets`, `jobs` (grants and RLS as in the queue spec §7) |
| R.12 | the Publish summary lists agent-changed files since the last Publish |
| R.13 | the fetch proxy refuses Alembic hosts, private and metadata addresses, long queries and token-bearing URLs |

## 10. Round 2 resolutions (G7 round 2) — these rules take precedence

1. **Keeping the token out of the agent's reach (H6):**
   - **production:** the agent runs as a non-root user with no sudo, `/proc`
     is mounted with `hidepid=2`, and ptrace is disabled (`yama ptrace_scope
     = 3`); the sidecar runs as another user, holding the token and the AI
     key in memory only;
   - **testing (instabox, one VM):** each course's Linux user reaches the
     agent API and the gateway only through **its own local proxy port**
     (nftables owner match → a per-course port), and that proxy holds the
     course's token. No VM-wide secret is used for the session token.
   R.7 also checks that the agent user can't read the sidecar's environment
   or memory, and that one course's user can't use another course's proxy.
2. **Allowed hosts (R-3):** the machine firewall allows the gateway, the
   fetch proxy and the agent API (Alembic's API host, whose addresses are
   resolved and pinned by the orchestrator when the sandbox starts, renewed
   on change). Nothing else.
3. **Re-offering repeats every refusal (R-7):** the 30-second job re-runs
   §4.1 steps 1–4 (token still valid, paths, read-only course, paused
   reasons) before queueing a pending changeset.
4. **Automatic jobs are capped at co-author rights at every check (R-10):**
   the changeset records `rights_cap = 'co-author'`, and both §4.1 step 3
   and the committer's re-check use `min(invoker role, rights_cap)`.
5. **Public records are checked (R-5):** the publish profile's output is
   run through the answer-key and copying checks like any public file, with
   all text fields of a record concatenated, so passages split across
   fields can't slip under the 12-word limit.
